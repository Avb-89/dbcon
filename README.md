# dbcon

***

dbcon консольная утилита для работы с  SQLite. Он работает как инструмент командной строки, интерактивная оболочка и локальный MCP-сервер.

# Установка на macOS

Скачай исполняемый файл `dbcon` из раздела [Releases](https://github.com/Avb-89/dbcon/releases). В терминале перейдите в папку с загруженным файлом и выполни:

```sh
mkdir -p "$HOME/.local/bin" && mv ./dbcon "$HOME/.local/bin/dbcon" && chmod +x "$HOME/.local/bin/dbcon"
```

Для стандартной оболочки macOS — zsh — добавь каталог в `PATH`:

```sh
echo 'export PATH="$HOME/.local/bin:$PATH"' >> "$HOME/.zshrc" && source "$HOME/.zshrc"
```

# Что умеет

### Показывать структуру базы

dbcon перечисляет таблицы и показывает структуру их столбцов: имена, типы, признаки обязательного значения, значения по умолчанию и состав первичного ключа. Через MCP также доступно SQL-определение таблицы.
### Читать и искать записи

Можно выбрать таблицы и поля, ограничить число результатов и задать порядок вывода. Поиск работает по подстроке или полному совпадению, с учётом регистра или без него. Искать можно как по выбранным полям, так и по конкретному полю независимо от состава вывода.

Несколько поисковых условий объединяются по принципу «должны выполняться все». Для более точного отбора доступны фильтры со сравнениями, проверками `NULL`, логическими `AND` / `OR` и скобками. Поиск, фильтрацию и сортировку можно сочетать.

### Работать с JSON внутри SQLite

Если столбец содержит JSON, dbcon умеет обращаться к отдельным значениям по пути — например, `data:$.text` или `data:$.meta.author`.

Такие значения можно выводить, искать, фильтровать, сортировать и проверять на заполненность.

### Считать, не выгружая содержимое

Программа считает все строки или только те, которые проходят условия поиска и фильтрации. Отдельно можно посчитать строки, где хотя бы одно из выбранных полей непустое.
## Три способа работы

### 1. Команда в терминале

Один запуск выполняет запрос и завершает работу. Такой режим подходит для быстрых проверок и вызова из скриптов.

Например, посмотреть таблицы существующей базы:

```sh
dbcon --db ./work.db --tables
```

Для чтения доступны два представления: отдельные блоки с полными значениями и компактная таблица. В компактном виде длинный текст сокращается под ширину терминала; блочный вывод сохраняет его целиком.

### 2. Интерактивная оболочка

Если запустить dbcon с выбранной базой без отдельного действия, откроется оболочка. В ней можно последовательно изучать таблицы, читать записи, искать и считать, не открывая подключение заново для каждой команды.

Команды выполняются по `GO`, выход — `QUIT` или `EXIT`. Есть сокращённая форма `SELECT … FROM … LIMIT …`, но оболочка не является универсальной SQL-консолью.

### 3. MCP для ИИ-ассистента

В режиме MCP dbcon предоставляет клиенту четыре инструмента с параметрами:

| Инструмент | Назначение |
|---|---|
| `list_tables` | Узнать, какие таблицы есть в базе |
| `describe_table` | Изучить столбцы и определение таблицы |
| `read_rows` | Прочитать или найти записи с фильтрацией и сортировкой |
| `count_rows` | Посчитать записи, в том числе с условиями |

Клиент запускает dbcon как локальный процесс и общается с ним через стандартный ввод и вывод. Отдельный сетевой сервер и открытый порт не нужны.

Ассистент может сначала изучить структуру, затем выполнить точечный поиск и прочитать найденные записи. Результаты передаются в структурированном JSON; значения полей не обрезаются под ширину терминала. Объём выборки можно ограничивать и читать данные порциями.

При этом dbcon — не сама «память» модели и не семантический поисковик. Он предоставляет доступ к данным и буквальный поиск; выбор запросов, интерпретация результатов и восстановление контекста остаются задачей ассистента. Работа MCP также зависит от поддержки инструментов конкретным клиентом и моделью. Примерял на chatgpt. и несколько локальных моделей .

## Подключение и безопасность

Базу можно указать непосредственно при запуске или сохранить подключение в JSON-конфигурации. Для создания и выбора конфигурации предусмотрен интерактивный мастер. 

- dbcon открывает существующий файл SQLite
- Без конфигурации, меняющей режим доступа, подключение по умолчанию открывается только на чтение; 
- **MCP всегда работает только на чтение**
- Имена таблиц и полей проверяются, а значения фильтров передаются в SQLite как параметры. Фильтры не являются способом выполнить произвольный SQL.

## Границы текущей версии

- Добавление, изменение и удаление записей пока не реализованы. Флаг `-w` открывает подключение с правом записи, но не добавляет команды редактирования.
- Нет выполнения произвольных SQL-запросов, объединения таблиц через `JOIN` и произвольных SQL-агрегаций.
- Поиск буквальный, без векторного индекса и поиска по смыслу.
- Временные метки возвращаются как хранятся в базе, без автоматического преобразования в даты.
- Каждый MCP-запрос работает с одной таблицей; связанные данные ассистент получает отдельными вызовами.

Текущая реализация написана на Swift с использованием SQLite3 и ориентирована на macOS.
